## VaultCrates 1.1.3 — Hologram fix

**Bugfix release for every supported Minecraft version — pick the jar that matches your server:**

| Server | Jar | Java |
|---|---|---|
| Paper 1.21 – 1.21.11 | `VaultCrates-1.1.3+1.21.x.jar` | 21+ |
| Paper 26.1.x | `VaultCrates-1.1.3+26.1.x.jar` | 25+ |
| Paper 26.2.x | `VaultCrates-1.1.3+26.2.jar` | 25+ |
| Paper 26.3.x | `VaultCrates-1.1.3+26.3.jar` | 25+ |

From now on, VaultCrates follows semantic versioning: every Minecraft line gets the same version number, and the part after `+` only names the Minecraft target.

### 🐛 Fixes
- **Holograms disappeared after a server restart** — or once nobody had been near the crate for a while — and only came back with `/vc reload`. They now reappear automatically whenever the crate's chunk loads. ([#1](https://github.com/itsLarss/vaultcrates/issues/1))
- Hex colours, MiniMessage and `:icons:` now render correctly in hologram lines

### ⬆️ Updating from 1.0.1 on Minecraft 1.21.x?
This is the first 1.1.x build for 1.21.x, so it also contains everything from 1.1.0:
- **NPC crates no longer open without a key** — NPC links run the same key, permission and economy checks as the crate itself
- `/vc linknpc` now works (Citizens by NPC id; FancyNpcs/ZNPCsPlus via `/vc linknpc <crate> fancynpcs <name>`)
- `Glow: true` no longer blocks `/enchant` and anvils; `Glow: false` also hides ItemsAdder's own glint
- ItemsAdder 4.x furniture crates (display + hitbox) work and can no longer be picked up by IA
- Shift + left-click on a furniture crate shows its ID instead of deleting it — remove with `/vc remove <id>`
- MMOItems, ExecutableItems, VaultUnlocked and ItemsAdder `:icons:` work with current plugin versions
- Enchantments from enchant plugins via namespaced ids, e.g. `"myplugin:soulbound": 1`
- Startup `NullPointerException`, purple/italic GUI lore, false "Another crate is too close" warnings and config resets on `/vc reload` with YAML errors are fixed

Your configs and data are kept — no manual migration needed.
